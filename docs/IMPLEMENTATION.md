# Light-PS implementation status

更新时间：2026-09-20

## 已完成的 v0.1 功能切片

当前版本已经覆盖一条可用的浏览器编辑闭环：

- 固定逻辑分辨率画布，与 CSS 缩放和 DPR 解耦。
- PNG、JPEG、WebP 导入、粘贴与拖拽；多图层排序、显隐、锁定、不透明度与混合模式。
- 图层移动、缩放、旋转、翻转；矩形选区与裁切。
- 画笔、可恢复擦除、基础亮度/对比度/饱和度调整。
- 独立重绘遮罩；合成图与严格不透明黑白 Mask 分别导出。
- 有界撤销/重做、工程文件 `.lightps` 保存/打开、IndexedDB 自动恢复。
- 同页 `window.__LIGHT_PS__` API 与带来源校验、显式授权的 iframe MessageChannel 通信。
- 远程写入的版本冲突检查、重复请求幂等、输入/素材/工程大小限制。

工程模型、像素渲染和 UI 已分层。Fabric 只负责视口与直接操作，导出的像素由独立栅格管线生成，因此视口缩放不会改变产物尺寸。

## 验证证据

在 Node.js 24.15.0 环境执行：

```sh
npm ci
npm test
npm run build
```

结果：5 项模型/状态单元测试通过，生产构建通过。当前构建产物约 665 KB 未压缩、约 205 KB gzip；Vite 会提示主 chunk 超过 500 KB，后续接入组件库时应优先做代码分割和按需加载。

使用真实浏览器完成两组验证：

1. 栅格与工程测试：原生分辨率、跨图层 multiply、擦除与恢复、独立 Mask、二值像素纯度、Inpaint 覆盖层隔离、工程往返与损坏工程拒绝，共 9 项。
2. 交互验收：无页面横向溢出、图层拖动与撤销、显隐/混合/调整、擦除与恢复、独立 Inpaint、选区/裁切与撤销、Agent 幂等与版本冲突、非法命令保护、图片/工程下载、刷新恢复，共 20 项。

## 运行与交付边界

```sh
npm run dev -- --port 5176 --strictPort
```

目前实现是浏览器本地应用，不需要图片处理服务器、登录或常驻后台服务。浏览器缓存用于恢复最近工程；正式交付仍建议用户下载 `.lightps` 工程作为备份。

PSD 完整读写、文字/矢量/智能对象、云素材库、MCP，以及 TapNow、LightAI、Figma 的专用适配器暂未实现。现有桥接协议已经为这些宿主提供稳定的最小接入面，但不会假装已经完成专用插件。

性能限制目前偏保守：单工程最多 10 个图层、单素材最多 80 MB，并未承诺 4K 多图层重度滤镜场景。后续需要基于真实素材补充压力测试，再决定是否引入 Worker、分块缓存或 WebGL。

## 下一步

功能验收后进行 UI 优化。届时接入用户现有 React 组件库，优先替换顶栏、工具栏、图层列表、检查器和弹窗的视觉/交互层；核心文档模型、栅格导出、桥接协议与浏览器验收保持不变。
